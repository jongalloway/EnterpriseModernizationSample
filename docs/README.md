# Documentation Layout

Use this tree to keep the modernization story legible instead of mixing planning, legacy notes, and target-state guidance together.

- `docs\before\` — the legacy estate as it exists today: behaviors, topology, screenshots, and operational notes.
- `docs\after\` — the target-state architecture, migration plans, and post-cutover guidance.
- `docs\foundation\` — scenario framing, naming, package baselines, and other repo-shaping references that both states depend on.

Keep new documents inside the seam they describe so downstream work can evolve before/after content independently.
